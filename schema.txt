MarineScraper — PostgreSQL Schema
==================================

Table: captures
---------------
Stores one row per region per scrape run.

  id              BIGSERIAL PRIMARY KEY
  region          VARCHAR(8)        -- Single-letter region code (e.g. "N", "S", "P")
  region_name     VARCHAR(128)      -- Human-readable name (e.g. "Suez North")
  captured_at     TIMESTAMPTZ       -- When the scrape happened
  ingested_at     TIMESTAMPTZ       -- When the row was inserted (auto-filled)
  filepath        TEXT              -- Path to saved screenshot (if --save-images)
  is_north        BOOLEAN           -- Legacy flag for Suez North
  zoom            SMALLINT          -- Map zoom level used
  status          VARCHAR(16)       -- "success", "partial", or "error"
  file_size_kb    REAL              -- Screenshot file size
  tiles_total     INTEGER           -- Number of tiles attempted
  tiles_ok        INTEGER           -- Tiles successfully captured
  tiles_failed    INTEGER           -- Tiles that failed
  tankers         INTEGER           -- Total tanker count (red markers)
  cargos          INTEGER           -- Total cargo count (green markers)
  moving_tankers  INTEGER           -- Moving tankers (arrow-shaped)
  moving_cargos   INTEGER           -- Moving cargo ships (arrow-shaped)
  markers         JSONB             -- Array of detected markers with lat/lon/type/motion
  detections      JSONB             -- Per-tile detection breakdown

  UNIQUE (region, captured_at)


Table: vessel_positions
-----------------------
Stores one row per detected ship marker. Positions are derived from
pixel-based OpenCV detection, converted to geographic coordinates
via Web Mercator projection. Ships are anonymous — no identity data
(MMSI, name, flag) is available from pixel detection alone.

  id              BIGSERIAL PRIMARY KEY
  capture_id      BIGINT            -- FK -> captures(id), CASCADE on delete
  lat             DOUBLE PRECISION  -- Latitude (from pixel -> Web Mercator)
  lon             DOUBLE PRECISION  -- Longitude (from pixel -> Web Mercator)
  ship_type       VARCHAR(16)       -- "tanker" (red) or "cargo" (green)
  motion          VARCHAR(16)       -- "stationary" (circle) or "moving" (arrow)

  UNIQUE (capture_id, lat, lon)


Table: tile_captures
--------------------
Stores raw global tile captures. Each tile keeps its real screenshot timestamp
and queue provenance; marker arrays are not spatially deduplicated here.

  id              BIGSERIAL PRIMARY KEY
  tile_id         TEXT
  wave_id         TEXT              -- Canonical capture wave id
  enqueue_id      TEXT              -- Queue enqueue id (same as wave_id)
  batch_id        TEXT              -- Queue batch that produced the tile
  worker_id       TEXT              -- Worker that uploaded the batch
  captured_at     TIMESTAMPTZ       -- Actual per-tile screenshot time
  ingested_at     TIMESTAMPTZ       -- Raw database insert time


Table: capture_waves
--------------------
One row per global queue wave. Only status "completed" rows have a published
dashboard snapshot.

  wave_id             TEXT PRIMARY KEY
  enqueue_id          TEXT UNIQUE
  status              VARCHAR(16)   -- running, completed, or failed
  started_at          TIMESTAMPTZ
  completed_at        TIMESTAMPTZ
  snapshot_at         TIMESTAMPTZ   -- Shared dashboard timestamp
  batch_count         INTEGER
  expected_tiles      INTEGER
  captured_tiles      INTEGER
  successful_tiles    INTEGER
  failed_tiles        INTEGER
  raw_markers         INTEGER
  snapshot_markers    INTEGER
  tile_ids            JSONB
  coverage            JSONB
  summary             JSONB


Table: wave_vessel_positions
----------------------------
Atomically published dashboard markers for a completed wave. Higher zoom wins
when the same marker appears in multiple zoom levels; spatial overlap
deduplication only compares markers from different tiles.

  id                  BIGSERIAL PRIMARY KEY
  wave_id             TEXT              -- FK -> capture_waves(wave_id)
  tile_capture_id     BIGINT            -- FK -> tile_captures(id)
  tile_id             TEXT
  zoom                SMALLINT
  captured_at         TIMESTAMPTZ       -- Original tile capture time
  snapshot_at         TIMESTAMPTZ       -- Shared wave timestamp
  lat                 DOUBLE PRECISION
  lon                 DOUBLE PRECISION
  ship_type           VARCHAR(16)
  motion              VARCHAR(16)
